# i18n Conventions

- Three locale directories: `locales/en/`, `locales/fr/`, `locales/ar/`
- Every key in `locales/en/` must exist in `fr/` and `ar/`. `services/i18n/resources/resources.ts` enforces this at type-check (`satisfies ... typeof en`), not at `build`
- Extra fr/ar keys are not caught — delete them when you remove an en key
- Plurals: keep en's `_one`/`_other` in every locale. For new ar plurals also add `_zero`/`_two`/`_few`/`_many` (most existing ar plurals only have `_one`/`_other`; for any count whose Arabic category is zero/two/few/many — 0, 2, 3–10, 11–99, and again 103–110, 111–199, … — i18next then shows the en-GB fallback, i.e. English text, not the Arabic `_other`)
- New namespace: create the JSON in all three locale dirs, register it in `services/i18n/resources/{en,fr,ar}.ts` (camelCase key, e.g. `continuousScreening` for `continuous-screening.json`), and add the same key to `ALL_NAMESPACES` in `services/i18n/all-namespaces.ts`. `'user-scoring'` is a legacy kebab key; leave it as is
