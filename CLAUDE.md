# Marble Frontend

Bun monorepo (`packages/*`) on TanStack Start — SSR React 18 via Vite + Nitro — with TanStack Router, Query and Form, Radix UI, Tailwind 4, Zod, and Biome.

## Commands

Package scripts run through the workspace filter:

```bash
bun run -F app-builder dev          # dev server
bun run -F app-builder type-check   # tsc --noEmit (same script in every package)
bun run -F app-builder build
bun run -F app-builder unit-tests
bun run test:all                    # unit-tests across all packages
bun run format:write                # Biome
```

## Packages

- `app-builder` — the main app; the layout below describes it
- `backoffice` — separate back-office app
- `ui-design-system` — shared components, imported as `from 'ui-design-system'`
- `marble-api` — API client generated from OpenAPI specs
- `ui-icons`, `shared`, `typescript-utils`, `tailwind-preset` — support packages
- `tests` — e2e and integration

## app-builder layout

`src/` holds `routes/` (file-based: `_app/` pages, `ressources/` endpoints), `server-fns/`
(createServerFn handlers called from React Query), `components/`, `queries/` (one file per
query), `repositories/`, `services/`, `models/` (types with adapters), `middlewares/`
(`authMiddleware`, `servicesMiddleware`, `caseDetailMiddleware`), `schemas/` (Zod),
`contexts/`, `hooks/`, `utils/`, `locales/` (`en`, `fr`, `ar`).

Two trees are generated — edit the source and regenerate rather than the output:

- `src/routeTree.gen.ts` — regenerated by `dev` and `build`
- `packages/marble-api/src/generated/*` — `bun run -F marble-api generate-api`, from `openapis/*.yaml`

## Working agreements

- Work on a feature branch; agent edits on `main`/`master` are blocked by a hook.
- Finish with a clean `type-check`. A stop hook Biome-formats the files you touched and
  type-checks the packages you changed, and sends you back on failure.
- Reach for non-destructive git: `push --force`, `reset --hard`, `clean -f` and
  `checkout .` are blocked.
- After planning, `/dev-docs` persists the plan under `dev/active/[task-name]/`; run
  `/dev-docs-update` before compaction.

## Troubleshooting

Stale build output: `rm -rf packages/app-builder/.output && bun run -F app-builder build`

## Agent configuration

Path-scoped conventions live in `.claude/rules/`, which `.cursor/rules/*.mdc` wraps for
Cursor. Domain guidance and manual workflows are in `.claude/skills/`; subagents in
`.claude/agents/`. Codex reads this file via the `AGENTS.md` symlink and discovers the
same skills through `.agents/skills`. Codex hooks are registered in `.codex/hooks.json`
and run the scripts in `.claude/hooks/`. For how the pieces fit and where to put a new
one, read `.claude/claude-developer-guide.md`.
